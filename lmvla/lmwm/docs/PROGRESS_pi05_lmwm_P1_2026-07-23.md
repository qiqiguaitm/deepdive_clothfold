## 2. 机制深挖(4 个关键归因)

### 2.1 LMWM 信号质量:dino 坍缩 / 残差才有信息
- **dino LMWM(rvalley)MDN 模式坍缩**:π=[0.001,0,**0.992**,0.007],全程 **0 里程碑切换**,永远输出同一 code 分量 → hint 退化成当前 grid 的固定再编码。
- **so400m LMWM 健康**:π 多分量,t8 上 **14 段切换**,真分段。
- **⭐残差 >> 绝对**:hint = ĝ_next 中 **86% 是冗余当前态**;真子目标信号全在残差 ĝ_next−g_current:**残差 CV=1.1 vs 绝对 CV=0.12(10×)**。→ 注入绝对 hint 把 14% 信号淹没,注入残差直击冗余。

### 2.2 精度伤害的空间依赖性(直击 P1 blocker)
| | 聚合Δ | 与难度相关(corr) | 精度类平均Δ |
|---|---|---|---|
| A1(外挂DINOv3) | −0.81 | **+0.66(越难越伤)** | **−1.48** |
| A2(自身So400m) | −0.17 | +0.06(难度无关,平) | **−0.38** |
- **A1 外挂空间越难越伤**(t8 −10);**A2 自身空间几乎不伤精度**(−0.38)。→ **P3"同编码器空间"方向 = 精度安全的路,"救精度"半程已解决**。

### 2.3 t8 是控制受限非规划受限(为何高层 hint 帮不上)
- t8 真实成功判据 3 谓词:pot1 在灶 + pot2 在灶 + **开灶按钮**。失败分解:**卡在两壶中有一个抓/放失败**,开灶从不是瓶颈。
- 失败 = moka 壶手柄难抓 + 小灶面精准放置 + 长程复合误差。**纯操作精度硬瓶颈** → 高层子目标 hint 天然帮不上,对症是残差/suffix(少扰动)+ 控制侧(RTC)。

### 2.4 replan 暴跌根因(架构侧,附带发现)
- t8 replan 对比:replan=5 **70%** > replan=1 45% > replan=2 **30%**。
- 根因:**pi05 chunk 是 ease-in 速度剖面**(前几步缓慢起步,发力在后段);replan=2 只执行前2步 = 只做缓慢起步、丢掉发力段 → 机器人爬行/超时。
- **架构缺陷**:chunk 无跨边界速度连续性。对症 = **RTC(pi0_rtc,前缀条件 guidance,仓库已有)**,非降 replan。

## 4. 训练速度分析 + 优化点 ⚠️

- **实测 2.4-2.6 s/step,单训练 ~20 小时(30k步)** —— 慢。
- **瓶颈 = 数据加载**:North-E 训练数据(huanqian mujoco3.3.2)**无 frame_cache**,每步 pyav 解 AV1 视频(3相机×batch128),GPU 大概率在等解码。本机 LIBERO_fastwam 有 frame_cache 但训练用的是 North-E 副本。
- **优化选项(按性价比)**:
  1. **num_workers ↑**(当前8)+ prefetch → 更多并行解码(若 data-bound,cheap,改config)。
  2. **预解码 frame_cache**(North-E 生成)→ 消解码,step→compute-bound(~0.5-1s),**2-4× 提速,20h→6-10h**。
  3. AV1 → h264/raw 重编码 → 解码更快。
  - ⚠️ 改 pipeline 需重启训练,当前 40% 的不动,**只对新训练(a2_residual_suffix)启用**。

## 9. ⭐ tsched 消融: 残差效应是 **residual × tsched 交互**, 非残差单独(2026-07-24)

`resid_noTs`(残差, 去掉 `LMWM_MS_TSCHED=2.0`; 单变量, `MS_RESID_SCALE=1.0` 是默认 no-op)4×单卡 eval, n=4:

| task | base(tsched, 无残差) n=8 | resid_withTs(两者) n=6 | **resid_noTs(残差, 无tsched) n=4** |
|---|---|---|---|
| t0 指引 | 99.0 | 94.7 | 98.0 |
| t3 精度 | 99.2 | 100.0 | 97.5 |
| t4 精度 | 97.8 | 95.7 | 97.0 |
| **t6 指引** | **85.0** | **77.3** | **83.5** |
| **t8 精度** | **90.0** | **95.0** | **89.0** |
| **t9 精度** | **85.8** | **93.7** | **87.0** |

**结论**: `resid_noTs` ≈ `base`(t6 83.5≈85.0, t8 89.0≈90.0, 聚合 95.10≈95.22)→ **去掉 tsched 后残差的精度↑/指引↓全部消失**。
→ **§8 的"残差=纯精度旋钮"需修正为: 残差 × tsched 的交互才是精度旋钮**; 任一单独都不产生偏移。

**机制**: tsched = 按扩散时间步调度 ms-drop(hint 只在特定去噪相位出现); 残差 = hint 只含 delta。
**"相位定向 + 纯delta"同时成立**时 hint 才成为精细修正信号 → 精度涨(代价: 指引任务失去强子目标信号);
单有 delta 但全相位出现 → 稀释; 单有相位定向但含冗余当前态 → 无精度增益。

**对幅度门控(§8破局主线)的意义**: 门控训练继承了 `tsched=2.0`, 正在"能表达该效应"的基座上 ✅;
门控是在 tsched 的**时间相位**之上再加**空间相位**(远→绝对救指引/近→残差保精度)自适应, 方向自洽。

## 10. ⭐ 幅度门控 eval 结果: 假设证否, 但定位了真破局点(2026-07-24, n=4 egl 4×单卡)

门控 `LMWM_MS_GATE=1`(alpha=‖r‖/(‖r‖+‖cur‖) 自归一化, 远→绝对/近→残差)训练 12500 步完成, 判定 eval:

| 工作点 | t6(指引) | t8(精度) | t4(精度) | 聚合 | 偏向 |
|---|---|---|---|---|---|
| 残差(delta+tsched) | 77.3 | **95.0** | 95.7 | 95.43 | 精度 |
| base(绝对+tsched) | 85.0 | 90.0 | 97.8 | 95.22 | 平衡 |
| **门控(自适应+tsched)** | **88.5** | 88.0 | 94.5 | **95.00±0.62** | **指引** |

**判定: 门控没破零和, 做了与残差相反的事——偏指引。** 精度类总 Δ=−4.1(t4 −3.3/t8 −2.0), 指引类 Δ=+2.5(t6 +3.5, **四配置最高**)。

**机制(为何偏指引非预期的精度)**: 自归一化 alpha 让 ms 目标成**逐样本混合**(时而绝对时而残差)→ 对粗指引无害(关键大转移处得强绝对→t6涨), 但**把精度需要的干净细信号搅浑**(混合目标更难学→t8/t4跌)。**单个 ms 通道服务两者, 任何目标选择(固定/自适应)都只在前沿上换点。**

**⭐三点确证 zero-sum 结构性**: base/残差/门控 t6+t8 前沿守恒(175/172/176.5), 聚合全卡 ~95.0-95.4。单 ms 通道无法解耦。

**⭐真正的破局点(修正主线)**: 门控其实**解决了指引**(t6=88.5 全场最高), 唯一软肋 t8=88(精度)——正是 **RTC(控制侧, 正交, 不碰 ms 通道)** 对症(§2.3: t8=控制受限非规划受限)。
- **新主线 = RTC ⊕ 门控**(门控高t6=88.5 + RTC 补 t8 88→95+): 若两者都成立 → 聚合破 96 → 逼近/破 96.4 P1。备选 RTC⊕base。
- RTC 推理期(pi0_rtc 前缀条件 guidance, 仓库已有), 不用重训; 但需确认在 LaWAM eval 路径已接线。
- 更彻底但更贵的备选: **双 ms 通道**(绝对-指引 + 残差-精度 各一路同时激活), 而非门控单通道。

## 附: eval 提速审计(2026-07-24)
- **egl 单卡串行是元凶**: harness 因 `MUJOCO_GL=egl` 多进程离屏渲染不安全, 把 `num_workers` 强制 25→1 → 每路全串行 ~10min/task(稳态), 单路 10task ~1.8h。
- **osmesa+25worker**: CPU 渲染对多 worker 安全 → 保住 25 并行, 单卡 ~2×(填 GPU 等渲染的空闲; 推理仍单卡=天花板)。SR 口径一致(t0 osmesa 96.6 vs egl 94.0, 噪声内)。
- **多卡分片(EVAL_ONLY_TASKS 已有 env 门, 零改代码)**: 10 task 分 8 卡, 每卡独立 server 只跑 1-2 task → **实测 ~26min/单seed(~4×, 非预估16min: server加载~6min+带2task的慢卡是长板)**。**代价: 单seed 无误差棒; 且要占整 8 卡节点, 队列满时排队反而更久**(实测 qjsqq 排 egl 判定后面 ~17min)。
- **口径核对**: 分片 osmesa 单seed 聚合 94.40 落在 egl 8-seed 区间 [93.6,96.4] 内, per-task 一致(t6 76 vs 77.3, t8 88 在高方差 88-100 内)→ **osmesa/分片无系统偏差**。
- **结论**: 误差棒 eval 用 8-seed osmesa(2×); 快速方向读数用 8卡分片(~26min); 队列拥挤时分片的整节点需求是硬约束。
